partyparty is a two-device, same-Wi-Fi product. The Mac is the DJ server; an iPhone is the guest player.

Review steps:
1. Launch partyparty. The app and guest room require no PartyParty account.
2. Connect the Mac and a default-configured iPhone to the same Wi-Fi network.
3. In the Mac app, choose "Mac output (everything)" or an available audio input and press Go Live.
4. macOS asks for System Audio Recording only when Mac output is selected, or Microphone only when an input device is selected. Local Network access is used to serve the room.
5. Scan the HTTPS QR code shown by the Mac with the iPhone. The Mac chooses direct mode on normal Wi-Fi. If the Wi-Fi isolates nearby devices, it uses an encrypted internet relay and explains the added latency in the Mac console.
6. Start playback on the iPhone, then lock it. Audio continues through native HLS/AVPlayer and lock-screen media controls remain available.
7. The wall view is available from the Mac app and displays the room QR plus guest posts and media.

The app does not create Wi-Fi networks, install privileged helpers, request an administrator password, or require Screen Recording. The Mac App Store build contains no Sparkle updater and uploads no session diagnostics. Relay mode transports live audio and lightweight room interaction without retaining posts, recordings, replays, or public event pages. Guest photos use a capped, throttled secondary path, and videos are disabled in relay mode so music remains the priority.

PartyParty requires `com.apple.security.network.server` because the Mac app
listens for inbound HTTPS connections from guest phones on the same Wi-Fi. It
responds by serving the guest listener interface, room API endpoints, and live
LL-HLS playlists and media segments. Guests connect to this server through the
HTTPS QR code displayed in the Mac app. Removing the entitlement would prevent
guest phones from connecting and would break the app's core functionality.

Privacy policy and support links are available in the app's Settings sheet.
