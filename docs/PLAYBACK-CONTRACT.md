# Playback contract

- Production: 500 ms segments, 150 ms parts, 48-segment window. Bounded capture buffering and nonblocking ffmpeg tees prevent backpressure; audio-core changes require supervised go-live testing.
- Fixed room target: `schedule.Delay = 2s`. MULTIVARIANT playlist: `EXT-X-START:TIME-OFFSET=-2.000,PRECISE=YES`; `PART-HOLD-BACK=0.6`. Never adaptive/per-phone. Do not use hold-back 2.9 or MEDIA-playlist EXT-X-START without PRECISE; both failed on real AVPlayer.
- Before uploading any playlist-geometry/positioning change, pass `scripts/soak-playback.sh`: ten minutes of real muted AVPlayer proving attachment, progression, declared target, and no backward movement. Use `scripts/bench-playlist-proxy.py` for unshipped candidate manifests. Keep the log. Unit/contract tests and post-upload soaks do not replace this check.
- Healthy playback is passive: no seeks or rate steering. Visible playback more than 150 ms off target for three 250 ms measurements receives a bounded muted correction in the same attachment. Require precise clock evidence, preserve the last heard source sample, and show Retry if alignment fails. Corrections remain available throughout the session; no per-session cap or escalating delay. See [synchronization.md](synchronization.md) for the September 16 owner-requested latency/recovery change and test procedure.
- Missing timing telemetry alone never interrupts audio. No corrections while Safari is hidden or the phone locked. Backward playback is unacceptable.
